# Proof-of-Product: AI Agents / Structured Data

## Goal

The goal is a proof-of-product (PoP) that demonstrates the main features of a future product
providing structured data through AI agents to paying customers,
but with some shortcuts in the implementation.
The intentions for this exercise are:

1. Demonstrate to stakeholders (investors, Rezolve AI, potential customers and ourselves) that
   we can build a relevant product for which customers are willing to pay.

1. To produce content for the marketing team.

1. For us to understand how to build it.

## Features

The PoP must demonstrate the key features of the intended product:

- Relevant and exciting data derived from raw blockchain data and other sources;

- A crucial part of making data "relevant" and "exciting" is presenting them as timeseries,
  rather than merely as block sequences: Time should be a first-class citizen!

- The final output is dynamically built from input data, i.e. with the SQL engine;

- AI agents interactively producing output (using the dynamic query engine) that is useful for potential customers;

- Payment system (based on x402) for easy, reliable and seamless transactions;

- All of this in a decentralised, "Web 3.0" environment.

## Shortcuts

Important is what users get out of it and what we need to learn in order to build it.
Implementation details are less important. We do not want, at this stage, to invest much
effort and time in aspects that are 1) not innovative in themselves 2) which have been built before
and 3) that demand a much effort. Some relevant shortcuts are:

- Data sources are predefined and built with the existing framework; they are not generated automatically
  or dynamically (e.g. through the SQL engine);

- It is acceptable to reuse existing demonstration code.
  We can reuse, for example, the existing "fake portal" instead of integrating the code
  cleanly with the SQD Portal;

- Instead of a full-fledged metadata engine, we built and validate metadata by hand.

Tasks to implement this solution:

1. Define relevant / exciting data

1. Implement pipelines to create these data from raw blockchain data and other sources

1. Describe the data (metadata) / define the metadata schema in the first place!

1. Upload the data to S3

1. Configure the scheduler to consider these data

1. Extend worker-side SQL engine code to handle them

1. Extend the Fake Portal to
   a) use generic metadata
   b) process arbitrary data described by these metadata and
   c) consider timestamps as search key

1. Extend DuckDB Extension to consider generic metadata

1. Implement AI agents that can
   a) derive SQL queries from natural language enquiries (using metadata)
   b) use DuckDB to execute these queries
   c) make responses available in suitable form (text / graphics)

1. Integrate agents with payment system (x402)
